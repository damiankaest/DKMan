# ADR 0004 · Keycloak und OIDC

Status: angenommen, Integration implementiert, Live-Flow noch abzunehmen.
Keycloak 26.8.1 stellt SSO und vier Realmrollen bereit. Browser verwendet den
offiziellen `keycloak-js`-Adapter, Authorization Code mit PKCE S256 und Token nur
im Arbeitsspeicher. Kein eigener Identity-Provider, Password Grant oder Admin-Bypass.

Core prüft RS256-Signatur gegen konfigurierte JWKS, exakten Issuer, Audience,
Ablauf und Subject. JWKS-Netzfehler liefern 503; ungültige Tokens 401; fehlende
Rollen 403. Nur konfigurierte URLs werden angefragt. Keine Token-Cookies im Core,
daher keine implizite Cookieauth für API-Mutationen; gleicher Origin und kein CORS.
Keycloak verwaltet Login-Cookies. API-Ratelimit und CSP liegen am Proxy.

Lokales HTTP/`sslRequired=none` gilt nur hinter dem Loopback-Binding. TLS/VPN und
Issuer-/Redirect-Anpassung sind vor Zugriff weiterer Geräte gesondert abzunehmen.
Secrets und erste Passwörter werden pro Installation erzeugt; Passwortwechsel beim
ersten Plattformlogin. Bootstrap-Masterkonto nach Einrichtung entfernen/deaktivieren.
Quelle: https://www.keycloak.org/securing-apps/javascript-adapter
